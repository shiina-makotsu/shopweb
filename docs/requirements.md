# ShopWeb 轻量自研商城需求文档

版本：v1.2 draft  
日期：2026-06-08  
技术基线：Laravel 13、Filament 5、Livewire、MySQL/MariaDB、PHP 8.3+

## 1. 项目目标

ShopWeb 是一个轻量自研商城系统，第一阶段不做复杂平台型商城，重点完成小团队可上线使用的交易闭环：

- 用户注册、登录、浏览商品、加购、结算下单。
- 用户上传付款凭证，由后台人工确认付款。
- 后台管理商品、订单、库存、优惠码、页面、站点设置。
- 后台参考 WordPress 的信息架构和操作体验。
- 前台参考 LiteCart 的朴素商城结构，并确保移动端自适应。
- 发布包支持 Windows/Linux 服务器解压后通过网页安装向导初始化。

## 2. 用户角色

| 角色 | 说明 | 主要权限 |
|---|---|---|
| 游客 | 未登录访问者 | 浏览商品、查看页面、加入购物车 |
| 客户 | 注册用户 | 下单、查看自己的订单、上传付款凭证、投票 |
| 会员用户 | 注册用户身份占位 | v1 仅保留身份字段和接口，后续再扩展会员价格/权益 |
| 运营 | 后台用户 | 管理商品、分类、页面、资源 |
| 财务 | 后台用户 | 查看订单、确认/驳回付款 |
| 仓库/交付 | 后台用户 | 查看订单、管理库存、标记交付 |
| 超级管理员 | 后台最高权限 | 全部后台权限、后台用户和系统设置 |

第一版使用 `users.role` 区分 `admin`、`operator`、`finance`、`warehouse`、`customer`，后台资源按角色做基础访问控制；使用 `users.account_type` 区分 `regular` 普通用户和 `member` 会员用户占位，会员功能后续扩展。

### 3.0.1 用户身份与公开主页

| 字段 | 说明 |
|---|---|
| 用户 ID | 注册必填，只允许英文、数字和下划线，不能重复，用于公开主页、搜索和私信路由 |
| 用户昵称 | 网站对外显示名称，可后续修改 |

### 3.1 商品状态与前台行为

| 商品状态 | 前台可见 | 可购买 | 可投票 | 库存/订单规则 |
|---|---:|---:|---:|---|
| `draft` 草稿 | 否 | 否 | 否 | 后台编辑态 |
| `concept` 概念 | 是 | 可选筹款/预购 | 是 | 可配置购买意愿、购买金额投票、筹款目标和正式发布奖励 |
| `presale` 预售 | 是 | 是 | 否 | 用户购买后订单进入未发货，等待实际进货/发货 |
| `incoming` 进货中 | 是 | 否 | 否 | 作为预售商品的进货批次副本存在，显示进货数量和国际物流进度 |
| `published` / `in_stock` 现货 | 是 | 是 | 否 | 原“发布”逻辑；下单/确认付款扣减库存 |
| `sold_out` 售罄 | 是 | 否 | 否 | 现货库存为 0 时自动变更为售罄，不允许购买 |

说明：

- “现货”沿用原 `published` 编码，后台展示名称改为“现货”，以减少旧数据迁移风险。
- “进货中”商品不是直接修改原预售商品，而是创建一条关联原商品的进货批次商品，展示进货数量、国际物流状态。
- 概念商品可配置投票和筹款。概念商品取消发售计划时，后台需要能按订单号/筹款记录辅助退款。
- 购买意愿投票和购买金额投票仅适用于概念商品，不适用于全部商品。

### 3.5 公告、论坛与私信

| 模块 | 说明 |
|---|---|
| 公告 | 后台可发布、删除、置顶公告，设置是否允许评论、未读是否弹窗；前台弹窗以圆角对话框展示标题、正文、查看详情和确认已读 |
| 未读 | 新用户默认所有已发布公告未读；铃铛显示未读数量；查看公告自动已读 |
| 论坛 | 后台可维护分区，用户可发帖和回复，后台可置顶帖子并删除帖子/回复 |
| 私信 | 登录用户可从评论、搜索结果或公开主页进入一对一私聊 |

论坛发帖支持预设模板，模板会预填 Markdown 正文并保存帖子模板类型，用户仍可自由编辑。当前模板包括普通帖子、交友自我介绍、相亲介绍与要求、寻找合租人、招租信息、找租/承租需求、资源发布。

| 发帖模板 | 主要字段 |
|---|---|
| 交友自我介绍 | 性别或自定义性别、性格、喜好、会的技能、常驻城市、希望认识的人 |
| 相亲介绍与要求 | 自我介绍、常驻位置、工作、物质/资产情况、对方外貌/性别/喜好/物质资产要求 |
| 寻找合租人 | 城市、租金预算、地段、设施、详细位置或交通、合租人期待、照片/视频附件 |
| 招租信息 | 地段、租金、押付方式、最短居住时长、设施、入住时间、租客要求、照片/视频附件 |
| 找租/承租需求 | 城市、预算、期望地段、入住时间、承租人简介、设施要求、看房时间 |
| 资源发布 | 资源名称、类型、适用场景、授权说明、使用方法、附件与预览 |

### 6.2 付款状态

| 状态 | 说明 |
|---|---|
| `pending` | 未提交凭证 |
| `submitted` | 已提交凭证 |
| `confirmed` | 已确认收款 |
| `rejected` | 凭证被驳回 |

当前实现中，用户上传付款截图后系统会做轻量初筛：普通订单有凭证路径和订单号时标记 `payment_auto_check_status=passed`，用户侧显示“已付款”，后台仍保留 `submitted` 作为待人工确认。钱包充值订单只有识别出的订单号和金额均完全一致时才允许自动确认并发放充值权益；此类自动确认订单仍进入后台付款复核列表并保留“确认收款 / 驳回凭证”操作，即使用户随后隐藏订单也不能从资金复核队列消失。后台确认只记录人工复核结果，不重复发放；后台驳回会收回该订单发放的钱包余额、停用并隐藏充值赠券，并把订单退回 `pending_payment`。被人工驳回过的充值订单后续重新提交凭证时不得再次自动确认。

### 9.3 Markdown 渲染要求

- 支持标题、列表、链接、图片、引用、代码块、表格。
- 支持 Font Awesome 图标短代码，格式为 `[fa:cart-shopping]`、`[fa:regular:heart 愿望单]` 或 `[fa:brands:github GitHub]`；前台渲染和后台预览均使用项目本地安装的 Font Awesome Free 图标库。
- 后台编辑器提供类似 VS Code 的编辑/预览/分屏预览按钮，可打开或关闭预览；Markdown 工具栏提供 Font Awesome 图标按钮，可搜索常用图标或输入自定义图标名后插入短代码。
- 前台商品评论、公告/页面评论和论坛发帖/回复输入区提供 Font Awesome 图标插入按钮，插入内容沿用同一短代码渲染逻辑。
- 后台编辑器支持插入图片附件，上传到公开资源盘后可在 Markdown 中引用。
- 图片允许引用资源库公开 URL。
- 前台渲染时必须做安全过滤，禁止脚本注入。
- 页面中的图片自适应宽度。
- 表格在手机端横向滚动。

### 9.4 页面模板与 404

自定义页面增加 `template` 字段，后台可选择预设模板并继续编辑标题、Slug、摘要、封面图、SEO 和 Markdown 正文。模板只提供功能面板和默认正文，运营仍可自由覆盖文案。

| 友情链接模板 | 自动展示后台维护的有效友情链接 |

404 页面必须始终包含返回首页链接；后台页面的标题、摘要、封面图和 Markdown 正文用于自定义 404 文案和图片。后台内容菜单提供独立的“404 页面”入口，保存后会写入并发布 `slug=404` 的自定义页面，避免运营必须在普通页面列表中手动寻找 404 配置。

### 16.1 域名、反向代理与相对路径

- 前台公开资源盘默认使用 `/storage` 和 `/uploads` 这类站内相对路径，避免域名、IPv4/IPv6 指向或 `APP_URL` 不一致导致图片、Logo、跳转地址指向错误主机。
- `APP_URL` 仍保留给 CLI、邮件、安装向导和少量框架场景使用，不作为前台图片和站内链接的唯一来源。
- Cloudflare、Nginx、负载均衡等反向代理部署时，需要配置 `TRUSTED_PROXIES`，让应用信任 `X-Forwarded-Host`、`X-Forwarded-Proto` 等头部，否则后台登录、HTTPS 跳转和会话 Cookie 可能出现域名访问异常。
- HTTPS 域名部署建议设置 `SESSION_SECURE_COOKIE=true`；`SESSION_DOMAIN` 留空可让当前访问域名自动生效，需要跨子域共享登录时再设置为 `.example.com`。
- 前台和后台响应会把同站绝对 URL 重写成相对路径；Livewire 自动注入的后台脚本、`data-module-url` 和 `data-update-uri` 也会在响应结束后再次重写，避免域名访问后台时登录、创建、保存、列表筛选等 Filament 操作因绝对 Host/Scheme 错误而无响应。
- 后台 Logo、favicon 与前台读取同一套站点设置，输出仍走站内资源 URL，域名访问时不会再回退成无 Logo 的文字状态。
- 如果请求没有到达 Laravel，而是云厂商或备案拦截页直接响应，代码层无法修复，需要调整备案、源站或服务器地域。
- 更新代码后必须执行数据库迁移和清理缓存；论坛页面依赖新版字段和视图缓存，未执行 `php artisan migrate --force` 或未清 `php artisan optimize:clear` 时，生产环境可能继续出现 500 或旧页面行为。

### 17.1 工程原则

- 以下要求为硬性开发约束，任何功能开发、修复、重构和上线操作都必须遵守，不能为了赶进度绕过。
- 遵循最小惊讶原则：页面状态、按钮行为和后台数据口径必须与用户自然预期一致；例如用户提交付款凭证后，前台统一显示“已付款”并停止展示付款码、付款倒计时和“待支付金额”，后台仍以“已提交付款凭证”保留人工审核口径。
- 遵循单一职责原则：控制器只负责请求校验和响应编排；业务状态变化放入 Service；文件/外部接口访问放入独立存储或网关类；页面只做展示，不直接承载复杂业务判断。
- 严格先测试后提交：提交 Git 前必须在本地测试环境运行与变更相关的 PHP 语法检查、功能测试和必要的浏览器交互验证；若测试覆盖不到交互细节，必须明确补测或说明风险，不能用“页面能渲染”替代交互测试。
- 不乱动生产环境：未经明确要求不得 SSH、拉取代码、执行迁移、清缓存、重启服务或修改生产数据；生产更新必须在本地验证通过后再执行，并优先使用文档化步骤。
- 添加功能必须做防御性编程：涉及 DOM 绑定、状态索引、金额、订单、库存、权限、上传、第三方接口、缓存和后台快速操作时，必须处理空值、旧数据、并发/重复点击、索引错位、权限不足和失败兜底。
- 类似功能优先复用或引用模板：相近的 UI、评论、奖励、钱包、预览卡片、编辑器工具、支付、订单状态和后台分页逻辑应优先复用既有组件、Service、Blade partial 或样式类；确需新增实现时必须说明原因并保持接口可复用。
- 后台“卡片预览 + 下方设置 + 可选拖拽排序”的交互统一复用 `App\Filament\Support\CardPreviewTemplate`：模板必须提供有边框和背景的容器、卡片、设置区块、暗色主题适配、卡片内容与表单状态同步、点击展开/收回对应设置项，以及在启用排序时右下角保存排序按钮。钱包充值、商品 SKU 和后续类似功能不得重复造轮子。
- 功能必须模块化：订单、支付、钱包、AI、内容、论坛、客服、报表、系统更新等模块的异常不能互相扩散。非核心日志、告警、统计、自动校验失败时，不得阻断核心交易主流程。
- 所有可失败的外部边界必须有兜底：文件上传、Git 更新、第三方 API、邮件、Bot 告警、缓存、报表统计等都应捕获异常并返回可读结果。
- 前台和后台必须有 500 防护：生产环境服务端异常返回独立 `errors/500` 页面；该页面不得依赖数据库、站点设置、自定义页面或复杂组件，避免错误页二次报错。
- 新增数据库字段必须通过迁移实现；涉及线上拉取的提交说明必须写出迁移表/字段，避免落后版本仓库拉取后字段缺失导致 500。
- 关键链路必须有回归测试：支付、订单状态、上传、后台快速操作、报表统计和系统更新至少覆盖成功路径和一个失败兜底路径。
- 售后需求“快速处理”按处理类型隔离字段：留言处理只更新状态、留言和完成时间，不得读写退款审批字段；处理留言必须追加保留历史记录。旧库缺少退款审批字段时通过幂等修复迁移补齐，不能让留言发送依赖无关字段。
- 订单管理快速预览仅对仍需后台确认收款的订单显示已提交付款凭证，支持图片点击查看和文字凭证；人工确认或驳回后必须立即隐藏，已人工确认的历史凭证仍可在订单编辑页审计查看。
- 物流费用按订单计费：同一订单只收取一次基础邮费，多仓分批发货不得把各包裹邮费相加；商品额外邮费不得按购买数量重复乘算。预售商品仅在明确设置“预售邮费仓库”或额外邮费时参与邮费计算，未设置邮费的预售商品必须保持 0 邮费，站点预售默认仓库只负责履约分配，不能被动产生费用。

## 21. 钱包与充值流程

### 21.1 数据库字段

钱包功能由 `2026_06_19_000001_create_wallet_tables.php` 提供迁移与补齐：

| 表 | 字段 | 说明 |
|---|---|---|
| `users` | `wallet_balance_cents` | 用户钱包余额，按基准货币最小结算单位保存 |
| `wallet_redeem_codes` | `code`、`name`、`amount_cents`、`usage_limit`、`redeemed_count`、`starts_at`、`ends_at`、`is_active`、`note` | 钱包兑换码，可由后台创建和管理 |
| `wallet_transactions` | `user_id`、`order_id`、`wallet_redeem_code_id`、`created_by_user_id`、`type`、`amount_cents`、`balance_after_cents`、`source`、`note` | 钱包流水，记录兑换、充值、订单抵扣、后台调整等来源 |
| `orders` | `wallet_payment_cents` | 普通订单或秒杀订单中由钱包抵扣的金额 |
| `orders` | `wallet_recharge_cents` | 钱包充值订单的充值金额 |
| `orders` | `is_wallet_recharge` | 标记该订单是否为钱包充值订单 |
| `site_settings` | `wallet_recharge_success_message` | 钱包充值成功后给用户展示的弹窗文案 |

### 21.2 前台流程

用户中心新增钱包页，显示余额、充值入口、兑换码入口和最近钱包流水。钱包兑换码提交后立即入账，并写入 `wallet_transactions`。钱包充值选项卡片按“标题 / 付款：x / 实际到账：总额 / 金额：基础金额+赠送金额+(赠券金额*数量)”展示；付款金额使用红色正常字体，实际到账使用加大加粗红色字体，拆分金额使用灰色字体。赠送余额为 0 时不显示该拆分项；赠券数量为 1 时省略 `*数量`，多种赠券继续用 `+` 追加。

钱包充值走现有支付流程：用户填写充值金额后创建一张钱包充值订单；用户按付款页上传凭证；严格自动校验通过或后台确认收款后，系统自动把 `wallet_recharge_cents` 加到用户钱包余额，并写入一条 `wallet_recharge` 来源的钱包流水。重复确认同一充值订单不会重复入账。自动确认的充值订单必须继续等待后台人工复核：复核确认不改变已发权益；复核驳回写入 `wallet_recharge_reversal` 负向流水并收回全部充值余额，即使余额已消费也形成等额钱包欠额，后续可用余额须先抵扣欠额；该订单生成的充值赠券统一停用并从用户侧隐藏，但保留后台审计记录。后台充值档位可配置“充值赠送优惠券”：一个充值档位可添加多条赠券规则，每条规则分别设置优惠金额/折扣、适用范围、有效期、最低订单金额、发放张数、总可用次数和是否允许同单叠加使用；默认不可叠加。不可叠加表示该规则发放出的每一张优惠券都不能和任意第二张优惠券同单使用，包括同一规则批量发放出的其它赠券。确认收款后系统自动生成现有优惠码体系中的普通优惠码并发放给用户，优惠码可继续在“优惠码”菜单查看、编辑和统计，不另建独立券码体系；用户手填充值金额若等于某个启用充值档位的实际应付金额，则复用该档位的赠送余额、赠券规则和订单商品名；若不匹配任何充值档位，则订单商品名显示为“钱包充值x元”。

普通购物车结算和秒杀订单支持钱包余额参与支付。若钱包余额足够覆盖整单，结算页显示“钱包余额支付”选项：用户选择后系统直接扣除钱包并自动确认付款；用户选择二维码、PayPal、口令红包等其他方式时不会扣除钱包余额。若钱包余额不足以覆盖整单，则系统先用钱包抵扣可用余额，剩余金额继续使用用户选择的付款方式，并保留后台人工确认流程。

### 21.3 后台配置

交易菜单新增“钱包兑换码”，用于创建、停用、查看兑换次数和维护钱包兑换码。钱包充值选项后台顶部只保留用户端充值页面整体预览，并复用 `CardPreviewTemplate` 在同一个容器内展示所有已配置充值卡片和后台专用“新增充值选项”占位卡；占位卡只用于后台新增入口，实际用户侧不会显示。点击预览卡片后在预览下方的统一设置区域展开对应标题和表单，再次点击该卡片只收回自己的设置，多个卡片设置可同时展开且互不影响。拖动预览卡片可调整显示顺序，预览右下角“保存排序”默认置灰，检测到顺序变化后才允许点击并复用钱包设置保存逻辑。保存有效新选项后自动生成下一张占位卡，删除选项后占位卡回退到末尾。付款设置中新增“钱包充值成功弹窗文案”，用于配置后台确认充值收款后用户看到的提示文本。

### 21.4 支付方式、新用户引导与夜间模式

本轮新增 `2026_06_19_000002_add_payment_method_to_orders.php` 迁移，在 `orders` 表增加 `payment_method` 字段，默认值为 `qr_code`。当前支持：

| 值 | 用途 |
|---|---|
| `qr_code` | 主二维码支付 |
| `fallback_qr` | 用户点击支付失败后切换备用二维码支付 |
| `red_packet` | 口令红包/文字付款凭证支付 |
| `wallet` | 钱包余额支付 |

购物车结算和秒杀结算页面均提供二维码支付、口令红包支付；当钱包余额足够覆盖整单时额外显示钱包余额支付选项。全额钱包支付会自动确认订单；钱包余额不足时形成“钱包 + 所选付款方式”的组合支付，剩余应付金额继续走付款凭证和后台人工确认流程。

### 22.2 业务口径

待付款订单在用户创建后如果超过后台付款设置中的时间仍未上传凭证，会由 `shop:orders-expire-pending-payments` 定时任务自动取消，并从用户可见订单中移除；付款页会显示倒计时。若订单已提交凭证、已确认付款或已取消，则不会被该任务重复处理。

成本条目不再默认“存在即计算”。仓储、平台等持续支出应保存为持续成本并标记生效；采购成本只在采购批次保存/同步后由采购模块自动生成采购触发成本，按采购批次、采购数量和采购次数进入统计；未采购或手动标记未生效的采购成本不会提前进入利润。多次采购会产生多组已生效采购成本，利润统计会把它们全部计入。

|---|---|

|---|---|

| 路由 | 说明 |
|---|---|
| `GET /ai-image/local-models` | 返回本地语言模型、生图模型、LoRA、runner 配置状态和模型目录。 |

| Endpoint | 输入 | 输出 |
|---|---|---|
| `POST {LOCAL_AI_RUNNER_URL}/chat` | `model`、`prompt`、`messages`、`parameters` | `message` 或 `text` |
